# 第一次接入 Agent

页面右上角的“使用指南”可以随时打开。概览和 MCP 连接页会根据已保存的连接、Agent 权限和有效接入密钥提示下一步；密钥已生成不代表客户端已经接通。

## 1. 添加服务账号

打开“MCP 连接”，在内置连接器中选择服务并点击“添加”。填写自己的 Token，或选择 OAuth 并在供应商页面确认账号与权限。OAuth 正常回调后自动返回平台并更新工具目录。GitHub OAuth 需要自己注册应用；也可以使用 PAT。

自定义服务使用“添加连接”，保存后点击该连接的“连接”。成功后点击“查看工具”。连接失败会在当前连接下面保留真实错误；检查服务是否启动、地址是否正确，需要登录时打开“授权与账号”。“更多操作”中保留编辑、刷新目录、健康检查、会话诊断和运行控制。

远程 HTTP 服务不需要配对设备。只有工具要在另一台电脑上执行时，才需要到“设备”页面配对，并在创建连接时选择该设备。平台直连和 Pi 桥接的本地进程在平台主机上运行。

同一服务可以接入多个账号。在内置连接器的“管理 / 已连接”菜单中选择“添加另一个”，使用不同名称区分个人、工作等账号；各连接分别保存凭证，再按连接为 Agent 选择工具。

## 2. 分配 Agent 权限

打开“Agent 配置”，填写名称，勾选允许使用的工具并保存。工具条目会显示所属连接，避免选错同名工具或账号。Prompt、Resource、Skill 和产物按各自选项授权。

服务账号接入与 Agent 权限分开管理。连接就绪后，未分配给 Agent 的工具不会因此自动开放。Agent 专属上游身份及按调用凭证隔离的身份在对应 Agent 工作空间中配置；缺少凭证时需要为该身份授权。

## 3. 复制客户端配置

在“已创建配置”中找到该 Agent，点击“生成接入密钥”。结果窗口会立即出现，点击“复制完整客户端配置”，选择客户端，然后把配置或 CLI 命令粘贴到对应客户端的 MCP 设置中。复制成功后页面会提示“已复制”。

完整密钥只在生成时展示，关闭窗口后不能从平台重新读取。日常“导出客户端配置”使用凭证占位符，需要填入自己保存的接入密钥。

配置后在客户端读取工具目录，确认已连接。也可到平台“工具目录”，先选择对应 Agent 身份再查看工具并测试参数；“执行工具”会触发真实调用。连接、授权、目录发现与工具测试无需模型，内置 Agent 推理才需要模型配置。
