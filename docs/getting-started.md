# 第一次接入 Agent

页面右上角的“使用指南”可以随时打开。概览和“连接”页会根据已保存的连接、Agent 权限和有效接入密钥提示下一步；密钥已生成不代表客户端已经接通。

全新部署里第一个注册的账号自动成为管理员，之后注册的账号是普通用户；自己的角色显示在左下角账号菜单和“个人账号”页。

## 1. 添加连接

打开“连接”，在内置服务中选择服务并点击“添加”。填写自己的 Token，或选择 OAuth 并在供应商页面确认账号与权限。OAuth 正常回调后自动返回平台并刷新工具列表。GitHub OAuth 需要自己注册应用；也可以使用 PAT。

自定义服务使用“添加连接”，填写后点击“保存并连接”，平台保存后立即连接并在该连接下面显示读到的工具数，成功后点击“查看工具”。连接失败会在当前连接下面保留真实错误和对应的下一步（地址访问不到、命令找不到、凭据被拒、设备离线等）；需要登录时打开“授权与账号”。上游换了地址或端口时，点“编辑连接”直接修改“MCP 地址”（本地命令则修改“启动命令”和“参数（每行一个）”），再点“保存并连接”；连不上时编辑窗口保持打开并给出原因。“更多操作”中保留编辑、刷新工具列表、健康检查、会话诊断和运行控制。

远程 HTTP 服务不需要配对设备。工具要在另一台电脑上执行时，到“设备”页生成配对码，选择系统并复制“安装连接命令”到目标电脑的终端；连接器会自动下载、校验并提示配对，无需目标电脑预装 Go、Node.js 或 connector。设备在线后点击“添加本机工具”，填写启动命令和参数（每行一个参数，也可粘贴 JSON 数组），点击“保存并连接”；结果直接显示在这台设备下面，再授权给 Agent。跨电脑接入须使用目标电脑可访问的平台 HTTPS 域名，不能复制 localhost 地址。运行位置选“平台服务器”（或 Pi 桥接）时，本地命令在平台服务器上运行。

同一服务可以接入多个账号。在内置服务的“管理 / 已连接”菜单中选择“添加另一个”，使用不同名称区分个人、工作等账号；各连接分别保存凭证，再按连接为 Agent 选择工具。

## 2. 分配 Agent 权限

打开“Agent”，点“新建 Agent”，填写“Agent 名称”，勾选允许使用的工具并保存。从某个连接的“给 Agent 授权”进入时，这个连接的工具已默认勾选。工具条目会显示所属连接，避免选错同名工具或账号。提示词与资源、Skill 和文件按各自选项授权。之后在 Agent 列表点“编辑权限”即可修改；点 Agent 名称打开“Agent 详情”，第一块列出它能用的工具及“在客户端中的名称”。

连接与 Agent 权限分开管理。连接就绪后，未分配给 Agent 的工具不会因此自动开放。Agent 专属身份及按调用凭证隔离的身份在“Agent 详情 → 高级”中配置；缺少凭证时需要为该身份授权。

## 3. 复制客户端配置

保存 Agent 权限后会直接进入“接入客户端”。先选择客户端（Cursor、VS Code / Copilot、Claude Desktop、Claude Code、Codex，或在“其他客户端”中选择），默认使用“浏览器授权（推荐）”：Cursor 和 VS Code 可点安装链接，其它客户端复制只含地址的配置。客户端首次连接会打开平台授权页，确认后即可使用，无需复制密钥。

客户端不支持 OAuth 时切换到“接入密钥”并点击“生成接入密钥”，在结果窗口选择客户端后复制配置或 CLI 命令。完整密钥只在生成时展示，关闭窗口后不能从平台重新读取；该 Agent 已有有效密钥时，可选择撤销旧密钥再生成，避免遗留多把有效密钥。日常“客户端配置（不含密钥）”使用凭证占位符，需要填入自己保存的接入密钥。

配置后在客户端刷新工具列表，确认已连接。也可到平台“工具”页，先选择对应 Agent 身份再查看工具并测试参数；“执行工具”会触发真实调用。连接、授权、读取工具列表与工具测试无需模型，内置 Agent 推理才需要模型配置。

## 工具在客户端里的名称

客户端看到的工具名是“英文标识\_\_工具名”，例如 `team_kb__search`。英文标识默认由连接名称生成；名称是中文时会退化成 `c3595bf` 这样的编号。在“添加连接”或“编辑连接”里填写“英文标识（工具名前缀）”即可换成有意义的前缀，表单会给出建议值。只有你主动填写或修改后工具名才会变化，升级平台不会改动已有工具名；修改后请在客户端刷新工具列表（`t_` 开头的旧式名称仍可调用）。
