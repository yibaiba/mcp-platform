## 失败与修复

首次选用既有开发 PostgreSQL 镜像缺少 pgvector，测试迁移失败；随后新建独立 pgvector 容器，迁移及重复迁移通过。未通过删除或重建业务数据绕过问题。

首轮完整回归发现代理连接池退出等待残留流，导致若干 afterAll 超时；现已区分轮换时排空与退出时中止并销毁，并新增真实未结束流检查。私有源保护测试沿用的可镜像预期也已改为符合私有来源规则。未放宽任何测试时限。

本机 Web 初次构建缺少共享 UI 的路径别名，现已按主 Web 配置补齐。浏览器脚本曾在测试路由启用后挂载静态网页、使用错误菜单定位，已修正并实际通过。Git 连通性曾仅检查进程退出码，现在还验证有效 HEAD，避免非 Git 响应被视为成功。

本机 Docker 构建在解析 `golang:1.27.3-bookworm` 基础镜像时遇到 Docker Hub TLS 握手超时，未执行到应用镜像构建，因而没有本机 Compose 通过结论。双架构镜像及 Compose 使用 PR 的原生架构任务验收，不能将本机失败记为成功。

补充的实际 Python Simple HTTP 索引检查发现 PEP 440 库的 `parse()` 返回值并未计算声明类型中的预发布标记；已改用 `explain()`，增加平台和真实 HMAC 设备共同查询带认证索引的回归，明确排除 rc/dev 与 yanked，保留 post/local 稳定版本。

## 设备断线后的检查失效修复（2026-10-29）

自然断线原先仅删除 WebSocket，遗留设备代次与能力信息，使先前包查询结果仍显示 `stale: false`。现在只在关闭的 socket 仍为当前连接时清理三项状态；旧 socket 延迟关闭不会清理已认证的新连接。能力检查先确认在线状态，避免把离线误报成需要升级连接器。保留历史成功结果并标记过期，之后的离线手动检查仍明确失败，不发起包安装或 MCP 调用。

真实 Go/HMAC 回归先复现旧结果未过期（9 项中 1 项失败），修复后 10 项通过；新增真实认证连接替换测试。测试使用新建隔离 PostgreSQL，单进程 60 秒硬超时。开始时一次迁移命令未显式传入隔离地址，读取了默认开发库并因已有表而失败，迁移事务回滚；随后显式指定新建测试库迁移成功，没有通过删除已有表绕过冲突。

运行包版本仍无通用进程证据采集；返回“未知”符合原先的证据要求，不把配置版本或缓存版本标为已验证。实际国内镜像、自建加速、远端设备和 Windows/Linux 安装/自启动仍缺对应环境验收；本次文档收尾不将这些项目改写为通过。
